# 安全弱點分析與修補

以可驗證的攻擊路徑確認根因，完成最小且可回復的修補。依使用者要求區分分析、掃描與修補；僅提供報告或要求檢視，不等於授權修改。

## 授權與範圍

使用者已要求修補時，在已授權範圍內完成確認、修改、必要測試及此次造成的修正，不逐弱點重問。多項已授權弱點可依序完成，各自保留可辨識的 diff 與驗證結果。

掃描發現超出原修補範圍的弱點，先回報根因、位置、影響與優先序；使用者未選定修補範圍時不自動全部修改。新增範圍、重大重構、公開 API／資料庫相容性取捨或額外外部操作，先說明具體差異並取得決策。

## 按輸入查閱

- 程式碼片段或弱點報告：先核對可用上下文；涉及實際 repository 行為時讀取相關程式碼，不能只相信報告。
- 明確要求掃描檔案或 repository：以搜尋工具定位可控輸入與 sink，讀 [patterns.md](references/patterns.md) 的相關語言與弱點條目。搜尋命中只是候選，不是漏洞證據。
- 硬編碼祕密、套件 CVE 或需要嚴重度校準：讀 [special-cases.md](references/special-cases.md) 的相關章節。

## 確認、修補與驗證

1. 確认攻擊者控制點、sink、可達路徑與既有防護，排除誤報。證據不足時標示未知與所需資訊，不假裝已確認。
2. 說明將改的檔案、根因修補方式及相關驗證；既有授權足夠就繼續。優先參數化、正確情境編碼、標準安全 API 與授權檢查，不自製黑名單或只隱藏錯誤。
3. 套用最小變更並檢查實際 diff；不以刪除核心業務邏輯消除弱點，不順手重構。沒有 Git 時以實際前後內容比對。
4. 執行與修補相關的正常功能、負向安全及有意義的邊界驗證，沿用既有 runner。確認不引入新的安全、相容性或邏輯問題；失敗、跳過及未執行如實回報。

不讀取或輸出 secret 真值，不自行輪替祕密、改寫 Git 歷史或操作正式環境。測試限於已授權範圍，不攻擊第三方系統。

## 交付

依實際結果回報：確認程度、根因與攻擊條件、影響、修補取捨、實際 diff（或可檢視的 diff 路徑）、驗證結果及未解事項。多弱點可用總表加個別證據，不固定八段，不用「不破壞功能」的保證代替測試。
