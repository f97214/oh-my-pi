# 第一性原理拆解

從使用者需要的結果與可查證限制出發，檢驗既有假設，提出最小可行方案。適合重要的需求或設計取捨；已明確的小改動不需套用本流程。

## 分析方法

- 先釐清問題、成功條件與現實限制，區分症狀和成因。
- 用反事實情境檢驗：拿掉這個需求或步驟後，必要結果是否仍成立？「刪除」在此是分析方法，不授權刪檔、移除功能或改變使用者需求。
- 挑戰會左右決策的假設，區分已驗證事實、使用者約束與仍待查證的推測；保留法規、相容性、成本與操作限制。
- 由必要結果建立最小方案，比較有實際差異的替代做法，說明取捨與失敗條件。
- 關鍵假設已有證據或明確標示、方案足以支持決策時收斂；不要為了理論純粹追求窮盡所有假設。

領域資訊不足時，先查明會影響決策的未知項；無法查證才詢問使用者。需求訪談可交由 grill；已成形產物的審查遵守專案規則，不強制串接其他 skill。

## 交付

依問題大小說明核心問題、關鍵假設及證據、建議方案、接受的取捨與未確認事項。必要時用比較表或推理鏈，不強制完整章節或檢查清單。提出建議不代表取得實作授權。
