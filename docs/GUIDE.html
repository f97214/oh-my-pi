omp 使用教學

從裝好到用得順手。這份文件是原創教學，不是上游文件的翻譯。

1. 開始之前

omp 是一個在終端機裡跑的 coding agent：你用自然語言交代事情，它讀你的程式碼、改檔案、跑指令，並在動手前依設定徵求你同意。

這份教學假設你已經把 omp 裝好了，目標是讓你從「能開起來」到「用得順手」。

這裡不會涵蓋的

主題去哪裡看
31 個工具的逐項參數omp.sh/docs/tools
60+ 供應商的完整設定docs/providers.md、中文版
設定鍵的完整清單docs/settings.md、config-usage.md
開發／貢獻這個 repodocs/DEVELOPMENT.md

版本落差怎麼辦。本文依 omp v17.3.4 撰寫。omp 更新很快，發現內容跟你的實際行為對不上時，以 omp --help 與 /help 的即時輸出為準 —— 那兩個是從程式本身產生的，不會過期。

2. 確認裝好了

開一個終端機，隨便一個目錄，打：

omp --version

印出版本號就代表沒問題，可以直接跳到下一節。

如果顯示「找不到命令」

代表 omp 的執行檔不在你的 PATH 上。這在 Windows 上特別常見 —— 用 npm 裝 bun 的話，Bun 的 global bin 目錄通常不會自動進 PATH。

Windows 的完整處理步驟（含備份與驗證）寫在 DEVELOPMENT.md 的「Windows：把 omp 加進 PATH」，這裡不重複。

改完 PATH 一定要開新的終端機視窗。既有的視窗抓的是舊 PATH，不會自己更新。這是最常見的「我加了但沒用」。

3. 接上模型

omp 自己不含模型，你得先接上一個供應商。最省事的是引導式設定：

omp setup

它會帶你選供應商、完成登入、設定預設模型。已經在 session 裡的話，用 /setup 開同一個流程。

OAuth 登入

Anthropic、OpenAI Codex、GitHub Copilot、Cursor 等支援用帳號登入而不是貼 API key：

/login

對應的 /logout 登出。訂閱制的 coding plan（Kimi Code、Z.AI／GLM、MiniMax 等）也走這條路。

用 API key

多數供應商認環境變數，例如 ANTHROPIC_API_KEY、OPENAI_API_KEY。也可以單次指定：

omp --api-key sk-... --model gpt-5.2

選模型：模糊比對

--model 不必寫全名，三種寫法都行：

omp --model opus              # 模糊比對
omp --model gpt-5.2           # 指定型號
omp --model openai/gpt-5.2    # 供應商/型號，最明確

想知道有哪些可選：

omp models

設成預設

不想每次都打 --model，就寫進 ~/.omp/agent/config.yml：

modelRoles:
  default: anthropic/claude-sonnet-4.5

default 只是十個角色之一，其他角色見第 9 節。

4. 第一個 session

先 cd 到你要處理的專案目錄，再開 omp。它會把當下目錄當成工作區根目錄：

cd D:/我的專案
omp

也可以開場就給指令：

omp "把 src/ 底下所有 .ts 檔列出來"

帶檔案進對話

@ 開頭的參數會被當成檔案讀進去，圖片也可以：

omp @prompt.md @screenshot.png "照這份規格實作，UI 參考截圖"

session 進行中一樣可以在訊息裡用 @ 引用檔案。

一次性使用

只想問一件事、拿到答案就結束，不進互動介面：

omp -p "這個 repo 的進入點在哪個檔案？"

-p 是 --print，處理完就退出，適合寫進腳本。

中斷與退出

動作怎麼做
中斷正在跑的回合Esc
退出/exit 或 /quit
看有哪些命令/help
看所有快捷鍵/hotkeys

5. 核心工作流

實際用起來就是一段對話。你交代目標，它會自己決定要讀哪些檔、跑什麼指令、改哪裡。

它會做的事

類別能力
讀檔案、目錄、壓縮檔、SQLite、PDF、notebook、網址，甚至 ssh:// 遠端路徑
找正規表達式搜尋、glob、結構化的 AST 查詢（支援 50+ 種語言文法）
改建檔、覆寫、以內容錨點做精準修補、結構化改寫
跑工作區 shell、持久的 Python 與 JavaScript cell
查LSP 診斷與導覽、DAP 除錯器、網頁搜尋

為什麼它改檔比較不會出錯

omp 的 edit 工具用內容雜湊當錨點，模型指出要改的位置而不是重貼整段程式碼。好處對你來說有兩個：改動更省 token，而且檔案在它讀完之後被改動過的話，錨點對不上，修補會被拒絕而不是覆蓋掉你的變更。

幾個實用習慣

  • 目標講清楚，過程讓它決定。「把這個函式的錯誤處理補上，失敗時回傳結構化錯誤而不是 throw」比「改一下這裡」有效得多。
  • 大工程先讓它規劃，見第 7 節。
  • context 快滿了就 /compact，或用 /shake 把工具輸出等大塊內容丟掉。/context 可以看目前用量分布。
  • 跑歪了就 /clear 清掉對話但保留 session，重新交代一次通常比一直拉回來快。

6. 核准與安全

omp 會改你的檔案、跑你的指令。核准模式決定它動手前問不問你。

模式行為適合
always-ask每個工具呼叫都問剛上手、或在不熟的專案
write只有會寫入的操作要核准，讀取類直接放行日常
yolo全部自動放行拋棄式環境、容器內

單次指定：

omp --approval-mode write

要持久設定就寫進設定檔的 tools.approvalMode。另有 --auto-approve 等同於全部放行。

在你真正在乎的 repo 裡不要用 yolo。它會讓 agent 在沒有任何確認的情況下刪檔、跑破壞性指令。要放手跑，先確定工作目錄已經 commit 過，出事才回得來。

更完整的機制（三個輸入來源、安全覆寫、子代理的處理）見 approval-mode.md 或中文版。

7. Plan mode 與省錢

先計畫再動手

Plan mode 讓 agent 只能讀、不能寫，先產出一份計畫給你看。改動大、或你還不確定要怎麼做的時候特別值得。

用 Alt+Shift+P 切換，或啟動時指定計畫用的模型：

omp --plan opus

計畫出來後可以用 /plan-review 重新打開檢視。

用便宜模型做粗活

典型的花費結構是：想清楚要做什麼很貴，照著做其實不用那麼貴。omp 有兩個機制利用這件事：

機制做什麼
--prewalk計畫的待辦清單成形後，在第一次寫入時自動切換到快而便宜的模型。session 內用 /prewalk 也能觸發
--plan-yolo開場強制唯讀計畫模式，模型第一次確認計畫時自動核准，然後切到 --plan-yolo-into 指定的模型去實作
omp --plan-yolo --plan-yolo-into smol

8. Session 管理

對話預設會存下來，可以隨時回去。

需求指令
接續上一個 sessionomp -c 或 omp --continue
挑一個舊的接續omp -r（不帶參數會開選擇器）
這次不要存omp --no-session
從 Claude Code 匯入omp --from-claude
從 Codex 匯入omp --from-codex

分支與樹狀導覽

session 不是一條線。你可以從中間某則訊息岔出去試別的做法：

命令作用
/branch從某則舊訊息開新分支
/fork從某則舊訊息分叉出新 session
/tree瀏覽整棵樹、切換分支
/handoff把目前脈絡交接給一個新 session

匯出與分享

命令作用
/export把 session 匯出成 HTML 檔（純本機）
/share產生加密連結分享已結束的對話
/collab把正在進行的 session 放上 relay，別人可即時參與
/viewcollab 的唯讀版：能看不能下指令

/share 與 /collab 的差別在時態：前者是分享成果，後者是找人一起跑。指令列也有對應的 omp share 與 omp join。

9. 模型與角色

omp 不是只用一個模型，而是依用途分配。角色有十個，常用的是這幾個：

角色用在
default一般對話
smol便宜的粗活、子代理 fan-out
slow需要深度推理的分析
planplan mode
commit產生 commit 訊息與變更紀錄

啟動時覆寫：

omp --model opus --smol haiku --slow gpt-5.2

session 中途換

方式作用
/model換這個 session 的模型
Ctrl+P在已設定的模型間循環
Alt+P臨時挑一個模型
Alt+M開模型選擇器並設定角色

思考強度

支援推理的模型可以調強度，從 off 到 max：

omp --thinking high

session 裡用 Shift+Tab 循環切換，Ctrl+T 切換思考區塊要不要顯示出來。

10. Slash 命令速查

在 session 裡打 / 會跳出補全。內建命令超過七十個，以下是最常用的。完整清單用 /help。

基本

命令作用
/help顯示說明
/hotkeys列出所有快捷鍵
/exit、/quit離開
/new開新 session
/clear清空對話但保留 session
/info顯示 session 資訊與統計

Context 管理

命令作用
/context顯示 context 用量分布
/compact手動壓縮 context
/shake丟掉工具結果與大塊內容
/fresh重置供應商串流狀態，不動本地對話

模型與模式

命令作用
/model、/switch換模型
/settings開設定選單
/vibe導演模式：驅動常駐 worker，自己只留唯讀工具
/goal目標模式：設定持續性的自主目標
/advisor開關第二個模型，讓它旁觀每一輪並提出意見

工具與擴充

命令作用
/tools顯示 agent 目前看得到的工具
/todo檢視或修改待辦清單
/jobs背景工作狀態
/agents開 agents hub
/mcp管理 MCP 伺服器
/extensions擴充套件控制中心
/reload-plugins重載所有 plugin

有些名稱是子命令而非頂層命令。例如 /on、/off、/status 屬於 /advisor；/add、/list、/remove 屬於 /ssh。打 / 讓補全帶你走最不會錯。

11. 快捷鍵

以下是預設值。/hotkeys 會顯示你這份組建實際生效的按鍵，包含你的自訂與擴充套件加的。

按鍵作用
Ctrl+P循環切換角色模型
Alt+P臨時挑一個模型
Alt+M開模型選擇器
Alt+Shift+P切換 plan mode
Shift+Tab循環思考強度
Ctrl+T顯示／隱藏思考區塊
Ctrl+O展開／收合工具輸出
Ctrl+R搜尋歷史輸入
Ctrl+G用外部編輯器編輯草稿
Alt+A開 Agent Hub
Alt+R重試上一個失敗的回合

要改按鍵，編輯 ~/.omp/agent/keybindings.yml：

app.model.cycleForward: Ctrl+P
app.plan.toggle: Alt+Shift+P

Windows Terminal 使用者注意。Ctrl+V 可能被終端機自己攔走，貼上圖片沒反應時改用 Alt+V。Ctrl+Enter 也會被吃掉，所以「排隊後續訊息」另外綁了 Ctrl+Q。

完整的 action ID 清單見 keybindings.md。

12. 再往下走

上面那些足夠日常使用了。想更進一步的話，這些是主要的擴充方向：

主題是什麼文件
Skills把重複的工作流包成可重用的技能，agent 需要時自己載入skills.md、中文
Extensions用 TypeScript 加工具、slash 命令、快捷鍵，與內建同一套 APIextensions.md
MCP接上 Model Context Protocol 伺服器，把外部系統變成 agent 的工具mcp-config.md
Memory跨 session 記住這個專案的事情memory.md
子代理task 平行分派工作，可隔離工作區，回傳結構化結果agent-hub.md、中文
Hooks在特定時機自動執行你的腳本hooks.md
魔法關鍵字散文中寫 ultrathink 等字啟動特化行為magic-keywords.md、中文

omp 也會直接讀你既有的設定 —— .claude、.cursor、.windsurf、.gemini、.codex、.cline、.github/copilot、.vscode 底下的 rules、skills 與 MCP 設定不需要轉換就能用。

13. 卡住的時候

症狀怎麼處理
打 omp 說找不到命令PATH 沒設好。見第 2 節，改完要開新視窗
模型回應失敗或串流卡住/fresh 重置供應商串流狀態；再不行用 /retry 或 Alt+R
context 爆掉/compact 壓縮，或 /shake 丟掉大塊工具輸出
它一直做錯同一件事/omfg 從你的抱怨產生一條規則，之後自動阻止該行為
改壞了想退回omp 不管版本控制。開工前先 commit 是唯一可靠的退路
貼上圖片沒反應（Windows）改用 Alt+V，終端機可能攔走了 Ctrl+V
中文變亂碼終端機編碼問題，設 PYTHONUTF8=1 或改用 UTF-8 主控台。不要改檔案編碼
想看它到底做了什麼/debug 開除錯工具；log 在 ~/.omp/logs/

還是不行

  • omp --help 與 /help 是即時從程式產生的，永遠比任何文件新
  • docs/README.md 是全部 80 多份文件的分組索引
  • GitHub issues
